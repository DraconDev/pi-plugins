## Objective

> Refactor the pi-plugin-list-selector-modlist extension to a safe, additive design: settings.json packages are the immutable baseline; modlist profiles are only addon packages layered on top via union merge. The existing replace-the-default behavior that introduced recent breakage is removed.

Concrete behavior after refactor:
- Config shape becomes `{ default: string, profiles: { [name]: string[] } }`. Each profile is a plain array of addon package strings (npm/git/local paths). No `tools`, no `extensions` wrapper, no `description` field.
- A profile named `none` with `[]` addons exists by default and is referenced by `default`. Switching to `none` leaves settings.json packages unchanged (additive union with empty array).
- Tool switching is dropped entirely. Profiles only carry addon packages. `pi.setActiveTools()` is never called by the extension.
- `/modlist save <name>` is removed. Profiles are authored by editing `~/.pi/agent/modlist.json` or `.pi/modlist.json` directly.
- Kept commands: `/modlist`, `/modlist list`, `/modlist status`, `/modlist <name>` (or `/modlist switch <name>`).
- On switch: read current `packages` from `~/.pi/agent/settings.json`; union with profile addons (dedup, preserve order); atomic write only the `packages` field back; then `ctx.reload()`. Other settings.json fields are never touched.
- Drift detection: status bar shows `modlist:<name>`; `!` suffix when addon packages have drifted from the active profile's intended set (a package is missing or an unexpected one is present).
- Safety: the modlist package itself is always preserved in settings.json even if a profile omits it. Unrelated packages in settings.json are never removed.
- Behavior unchanged: global + project-local config merging with project trust gating, atomic file writes preserving permissions, status bar display, `/modlist` interactive picker, `ctx.reload()` for package changes.

Out of scope: any change to skills, prompt templates, themes, providers, or model settings; backward compatibility with the old `{ tools, extensions }` profile shape; any new feature beyond the refactor.
